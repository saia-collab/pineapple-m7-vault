### ICM terminology correction

The official ICM method describes **five context layers numbered 0 through 4**. PM7's **four rooms** are our operating layout; they are not the same thing as the five ICM context layers.

| ICM layer | PM7 meaning |
|---|---|
| Layer 0 | Root agent rule: where am I? |
| Layer 1 | Root `CONTEXT.md`: where do I go? |
| Layer 2 | Task/stage contract: what do I do? |
| Layer 3 | Stable references: what rules apply? |
| Layer 4 | Working artifacts: what am I working with? |

Source: [RinDig Interpretable Context Methodology](https://github.com/RinDig/Interpretable-Context-Methodology).

## Definition of done

A PM7 task is DONE only when:

- it ran on the intended Windows computer or approved external system;
- it stayed inside the named scope;
- it created the contracted output in the exact path;
- deterministic validators passed;
- no prohibited action occurred;
- rollback exists when the task changed a system;
- a receipt records version, paths, hashes/results, and approval;
- the shared execution-state JSON was updated from that receipt.
